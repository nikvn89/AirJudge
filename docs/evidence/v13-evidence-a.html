Claim Window for Reserved Rewards in a GenLayer Reward Contract

This contribution adds a claim window to the AirJudge Intelligent Contract on GenLayer. Before the change, a reward reserved for an eligible applicant who never withdrew stayed locked in the campaign pool forever.

What was built

Every reservation now records the day it was made, taken from the transaction's committed datetime. The reward stays reserved for thirty days. After that, anyone can call release_expired_reservation, which returns the amount to the campaign's available pool and marks the application ELIGIBLE_EXPIRED. Until someone releases it, the applicant can still withdraw.

How it works

The day number is computed arithmetically from the ISO datetime, so every validator gets the same value. The release is deterministic and never calls a model. A new view, get_payout_window, returns the reservation day, the expiry day, today's day and whether the window has expired, and the web app shows "Claim by YYYY-MM-DD — N days left".

How it was tested

The contract was run in GenLayer's Direct Mode on the real GenVM SDK. Tests cover release one second before day thirty (rejected), release at day thirty (accepted, pool untouched), withdrawal after expiry but before release, and the treasury balance after each step. A mutation run confirmed that shifting the window by one day in either direction is caught by the tests.
